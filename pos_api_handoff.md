# POS API — что готово на бэке и что нужно на фронте

Привет! Бэкенд для POS-приложения готов. Ниже — все эндпоинты с форматами
запросов/ответов и что от тебя нужно по экранам.

## Важное про статусы

Пока в системе **два статуса платежа**: `success` (успешный) и `cancel`
(отклонённый). Возвраты (`refunded`) будут позже — добавим, когда появятся.
Пока их в макете можно не показывать или рисовать как 0.

Все суммы в **TJS**. Базовый префикс всех ручек — `/pos`.

## 1. Логин — два шага через SMS-код (OTP)

Вход по номеру телефона терминала. Пароля нет — вместо него одноразовый код
из SMS.

### Шаг 1 — запросить код

`POST /pos/otp/request`

```json
{ "phone": "+992XXXXXXXXX" }
```

Успех (200):
```json
{ "ok": true, "message": "Код отправлен по SMS", "expires_in": 300 }
```
`expires_in` — сколько секунд код будет действителен (сейчас 5 минут).

Ошибки:
- `404` — терминал с таким номером не найден
- `403` — терминал не наш мерчант (вход запрещён)
- `429` — код уже запрашивали только что, повтор через N секунд (текст в `detail`)

### Шаг 2 — проверить код

`POST /pos/otp/verify`

```json
{ "phone": "+992XXXXXXXXX", "code": "123456" }
```

Успех (200) — вход выполнен:
```json
{ "ok": true,
  "message": "Код подтверждён, вход выполнен",
  "terminalId": 12345,
  "terminalName": "Магазин на Рудаки",
  "storeName": "ООО Ромашка" }
```

Ошибки:
- `400` — код не запрашивался / истёк срок / неверный код
  (в `detail` для неверного кода приходит «Осталось попыток: N»)
- `429` — слишком много попыток, нужно запросить новый код

### Что нужно на фронте (экран логина)
- Экран 1: ввод номера телефона → вызов `otp/request`.
- Экран 2: ввод кода → вызов `otp/verify`.
- Таймер «Отправить повторно» на **60 секунд** (кулдаун бэка — раньше вернёт 429).
- Показ ошибок: неверный код (с остатком попыток), истёк срок, не наш мерчант.
- После 5 неверных попыток — предложить запросить новый код.

## 2. Экран терминала — инфо + последний платёж

`GET /pos/terminal?phone=+992XXXXXXXXX`

Ответ:
```json
{ "terminal": {
    "terminalName": "Магазин на Рудаки",
    "terminalPhone": "+992XXXXXXXXX",
    "storeName": "ООО Ромашка",
    "terminalQR": "..." },
  "last_payment": {
    "sender": "Душанбе Сити Банк",
    "sender_bank_id": 27,
    "amount": 150.00,
    "status": "success",
    "creation_datetime": "2026-09-08T14:12:00" } }
```

`last_payment` = `null`, если платежей ещё не было. `sender` — уже готовое имя
банка (не id).

## 3. Сводка за день — суммы и количество

`GET /pos/summary?phone=+992XXXXXXXXX&date=2026-09-08`

`date` необязателен — без него берётся сегодня.

Ответ:
```json
{ "date": "2026-09-08",
  "success": { "count": 21, "amount": 795.00 },
  "cancel":  { "count": 2,  "amount": 60.00 },
  "currency": "TJS" }
```

Считается на бэке (агрегация по базе), фронту фильтровать/суммировать не нужно.
Когда появятся возвраты — в ответе добавится блок `refunded` тем же форматом.

### Что нужно на фронте
- Плитки «Успешные» и «Отклонённые» за выбранный день (count + amount).
- Переключатель даты → передавать `date=YYYY-MM-DD`.

## 4. История платежей — по дням, с пагинацией

`GET /pos/history?phone=+992XXXXXXXXX`

Параметры (все необязательные, кроме `phone`):
- `date=2026-09-08` — один день
- `from=2026-09-01&to=2026-09-08` — период (обе границы включительно)
- `limit=50` — сколько записей вернуть (по умолчанию 50, максимум 200)
- `offset=0` — смещение для подгрузки следующих страниц

Если передан `date`, то `from`/`to` игнорируются.

Ответ:
```json
{ "terminal": { "terminalName": "...", "terminalPhone": "...",
                "storeName": "...", "terminalQR": "..." },
  "total": 137,
  "limit": 50,
  "offset": 0,
  "count": 50,
  "payments": [
    { "sender": "Душанбе Сити Банк",
      "sender_bank_id": 27,
      "amount": 150.00,
      "status": "success",
      "creation_datetime": "2026-09-08T14:12:00" }
  ] }
```

- `total` — всего записей под фильтром (для расчёта числа страниц).
- `count` — сколько вернулось на этой странице.
- `payments` отсортированы от новых к старым.

### Что нужно на фронте (экран истории)
- Список платежей за выбранный день/период.
- Подгрузка постранично: следующая страница = `offset += limit`.
- Дата/период — через `date` или `from`/`to`.

---

## Короткое резюме по экранам

1. **Логин**: `otp/request` → `otp/verify` (таймер 60 сек, обработка ошибок кода).
2. **Главная/терминал**: `GET /pos/terminal` (инфо + последний платёж).
3. **Сводка за день**: `GET /pos/summary` (плитки success / cancel).
4. **История**: `GET /pos/history` (фильтр по дате + постраничная подгрузка).

Если что-то в форматах неудобно для вёрстки (другие поля, другая структура) —
скажи, поправлю на бэке.
